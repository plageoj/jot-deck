# Jot Deck チュートリアル機能 設計書

## 1. 概要

### 1.1 目的

Jot Deck はキーボード操作特化型のパワーユーザー向けツールであり、`h/j/k/l` ナビゲーションや `g` プレフィックス、フォーカスモデル（Column / Card / Edit / Command）といった独自の操作体系を持つ。この操作体系は習熟すれば高速だが、初見では学習コストが高い。

本機能は、**初回起動時に操作方法を能動的に学べる導線**を提供し、また**任意のタイミングでいつでも再呼び出しできる**ようにすることで、新規ユーザーの離脱を防ぎ、既存ユーザーの操作再確認を支援する。

### 1.2 既存実装との関係

現状、初回起動時には「Getting Started」オンボーディング Deck（`Welcome` / `Navigation` / `Tips` カラム）が読み込まれる（`docs/003-roadmap.md` 3.6 / `deckData.svelte.ts` の `createOnboardingDeck()`）。これは**静的なコンテンツ提示**であり、ユーザーが実際にキー操作を試すインタラクティブな導線ではない。

本チュートリアル機能は、このオンボーディング Deck を**土台として活用しつつ**、その上にインタラクティブなガイドレイヤーを重ねる位置づけとする。両者は次のように役割分担する。

| 機能 | 役割 |
|:---|:---|
| **オンボーディング Deck**（既存） | 操作方法を記載した読み物コンテンツ。チュートリアル終了後も残る練習用 Deck。 |
| **チュートリアル**（本機能） | 初回起動時／任意呼び出し時に、実際のキー操作をステップごとに案内するインタラクティブなオーバーレイ。 |

### 1.3 設計方針

* **スキップ可能:** チュートリアルはいつでも中断できる（コーチマークの「Exit tutorial」、または読み物ステップでの `Escape`）。パワーユーザーを強制的に拘束しない。ハンズオン中の `Escape` は下層アプリへ透過する（§4.2）。
* **非破壊的:** チュートリアルはユーザーのデータを書き換えない。練習操作は専用のチュートリアル用 Deck（またはオンボーディング Deck）内で行わせる。
* **実操作ベース:** スライドを読ませるのではなく、実際にキーを押させて次のステップへ進める「ハンズオン」形式を基本とする。
* **再呼び出し可能:** コマンドパレット・キーバインド・設定画面の 3 経路からいつでも起動できる。
* **ローカル完結:** 進捗・完了フラグはローカルに保存。ネットワーク不要。

## 2. 起動トリガ

### 2.1 初回起動時（自動）

* アプリ初回起動を検出したら、チュートリアルの**起動を促すダイアログ**を表示する。
* 「初回起動」の判定は、後述の完了フラグ（`tutorial.completed`）と表示済みフラグ（`tutorial.prompted`）の両方が未設定であることをもって行う。
* ダイアログには次の選択肢を提示する。

| 選択肢 | 動作 |
|:---|:---|
| **Start tutorial** | チュートリアルを開始する。 |
| **Skip for now** | 今回はスキップ。次回起動時に再度ダイアログを表示しない（`tutorial.prompted = true`）が、コマンドパレット等からはいつでも起動できる。 |

> **Note:** 強制開始ではなく「促す」方式とする。パワーユーザーが既に操作を知っている場合に邪魔をしないため。なお、初回起動ダイアログは 1 回のみ表示し、以降は自発的に呼び出さない限り出さない。

### 2.2 任意呼び出し（手動）

ユーザーはいつでも次の 3 経路からチュートリアルを起動できる。

| 経路 | 操作 |
|:---|:---|
| **コマンドパレット** | `Ctrl+Shift+p` / `F1` →「Tutorial」コマンド（`docs/001-keybindings.md` 6.2 のコマンド一覧に追加） |
| **設定画面** | `Ctrl+,` → 「Help」セクションの「Start tutorial」ボタン |
| **キーバインドチートシート** | `?` / `Ctrl+/` 表示中のフッターに「Take the tutorial」リンクを配置 |

> キーバインド直接割り当て（例: `g ?`）は MVP では設けない。コマンドパレット経由で十分なため、必要が確認されてから追加検討する。

## 3. チュートリアル構成

### 3.1 形式

チュートリアルは**ステップ列**で構成される。各ステップは以下のいずれか、または組み合わせを持つ。

* **解説テキスト:** 何を学ぶかの説明（英語。`docs/000-spec.md` 8.2 のとおり全ユーザー向けテキストは英語）。
* **対象ハイライト:** 操作対象の UI 要素（カラムヘッダー、カードなど）を強調表示するスポットライト。
* **完了条件:** ユーザーが実際にそのステップの操作を行ったことを検知して次へ進む（ハンズオン）。完了条件のないステップは「Next」ボタン／`Enter` で進む。

### 3.2 コアトラック（必須ステップ）

フォーカスモデル（Column / Card / Edit）の習得と、新規ユーザーが「壊しても戻せる」と安心できることを主目的に、以下のステップを順に提示する。これらは初回起動チュートリアルで全員に通す。

| # | ステップ | 学ぶ操作 | 完了条件 |
|:---|:---|:---|:---|
| 1 | Welcome | チュートリアルの趣旨説明、Deck / Column / Card の階層 | Next |
| 2 | カラム間移動 | `h` / `l`（または `←` / `→`）でカラムを移動 | カラムフォーカスが移動したことを検知 |
| 3 | カードへ入る | `j` / `Enter` で Card フォーカスへ遷移 | Card フォーカスへ遷移したことを検知 |
| 4 | カード間移動 | `j` / `k` でカード間を移動 | フォーカスカードが移動したことを検知 |
| 5 | カード作成 | `o` で新規カードを作成し Edit フォーカスへ | 新規カードが作成されたことを検知 |
| 6 | テキスト入力と保存 | テキストを入力し `Ctrl+Enter`（または Vim モード時 `:wq`）で保存 | カードが保存されたことを検知 |
| 7 | Escape で戻る | `Escape` で上位フォーカスへ戻る | フォーカスが上位へ遷移したことを検知 |
| 8 | カラム管理 | `c` で新規カラム作成、`r` でリネーム、`d d` でカラム削除 | カラム作成を検知（リネーム・削除は紹介＋任意ハンズオン） |
| 9 | 削除と復元 | `d d` でカードを論理削除し、`u` で復元。続けて `g t` でゴミ箱（削除スタック）一覧 UI を開き、任意の項目を選んで復元できることを紹介 | 削除→`u` 復元の両操作を検知（`g t` は紹介） |
| 10 | コマンドパレットとチートシート | `Ctrl+Shift+p`（全機能の検索・実行）と `?`（全キーバインドのチートシート表示）の紹介 | Next |
| 11 | 完了 | 拡張トラック・主要機能（設定、Deck 切り替え）への案内 | Finish |

> **Note:** ステップ 9「削除と復元」は、論理削除＋削除スタック（`docs/002-data-structure.md`）という Jot Deck の安全網を体験させる重要ステップ。`u`（直近復元）に加えて `g t` のゴミ箱 UI（`TrashPalette`、`docs/003-roadmap.md` 3.7）を見せ、新規ユーザーが「削除＝消失」と誤解して操作をためらうのを防ぐ。

> **Note:** ステップ 8「カラム管理」で Deck / Column / Card の階層と CRUD を体験させ、ステップ 10 の `?` チートシートで以降の操作を自力で参照できる状態にして締める。

> **Note:** 各ステップの完了条件は、ユーザー設定でキーバインドがカスタマイズされている場合に備え、**キーそのものではなくアクション／フォーカス遷移の発生**で判定する（`docs/003-roadmap.md` 3.9 のキーバインドカスタマイズと整合）。チュートリアル UI に表示するキー表記は、アクティブなキーバインドレジストリから動的に解決する。

### 3.2.1 拡張トラック（任意ステップ）

コアトラック完了後、「Continue to advanced tips / Finish」を選ばせ、希望者のみ以下のステップへ進む。各ステップ単位でスキップ可能。Jot Deck の操作効率を引き出す機能群をカバーする。

| ステップ | 学ぶ操作 | 関連キー |
|:---|:---|:---|
| タグ | `#tag` 記法・入力補完（`Tab` 確定）と、タグによる Deck 全体の絞り込み | `#` / `/`（`/#tag`） |
| 並び替え | カラムの左右移動、カード のカラム内移動 | `H` / `L`（Column）、`J` / `K`（Card） |
| カラム間でカードを移動 | カードを隣のカラムへ移動 | `H` / `L`（Card フォーカス） |
| score（favorite） | カードのスコア増減（Twitter 風） | `f` / `F`（`+` / `-`） |
| コピー＆ペースト | カードの複製 | `y y` / `p` / `P` |
| 検索 | Deck 内検索 | `/` |
| Deck 切り替え・新規 Deck | 複数 Deck の切り替えと作成 | `Ctrl+p` / `g h`、`Ctrl+n` |
| カラム切り替え | カラム切り替えパレット | `g n` / `Ctrl+t` |
| 設定と Vim モード | 外観・Vim モード ON/OFF・キーバインドカスタマイズ | `Ctrl+,` |
| テーマ切り替え | ダーク / ライト切り替え | コマンドパレット「Toggle Theme」 |

> **Note:** Vim モードはデフォルト OFF（`docs/001-keybindings.md` / `docs/003-roadmap.md` 3.9）。「設定と Vim モード」ステップで**その存在を明示的に知らせる**ことに価値がある（Vim ユーザーが有効化に気づけるように）。

### 3.4 ステップ進行制御

| 操作 | 動作 |
|:---|:---|
| 完了条件の達成 | 次のステップへ自動前進（ハンズオンステップ、Observe 状態） |
| `Enter` / Next | 次のステップへ（読み物 / Next ステップ、Control 状態） |
| `Backspace` / `←` / Back | 前のステップへ戻る（Control 状態） |
| `Escape` | チュートリアルを中断（確認ダイアログ）。**Control 状態でのみ。** Observe 状態では下層へ透過するため、中断は `Tab` → Exit tutorial で行う |
| Skip step | このステップをスキップして次へ（ハンズオンが難しい環境向け） |
| Exit tutorial | チュートリアルを中断（コーチマーク操作部のボタン。`Tab` で到達、Observe 状態でも利用可） |

> **Note:** 進行キー（`Enter` / `Backspace` / `Escape`）はコーチマークにフォーカスがある **Control 状態**でのみ作用する。ハンズオンの **Observe 状態**では全キーを下層アプリへ透過し、完了条件の検知で自動前進する（§4.2）。これにより「Escape で戻る」「文字削除の `Backspace`」などのアプリ操作とチュートリアル操作が衝突しない。

## 4. UI 設計

### 4.1 レイヤー構成

チュートリアルは既存 UI の上にオーバーレイとして描画する。

* **スポットライト:** 対象要素以外を半透明マスクで暗転し、対象要素を切り抜いて強調する。
* **コーチマーク（吹き出し）:** 対象要素の近傍に解説テキスト・進行ボタン・ステップインジケータ（例: `3 / 10`）を表示する。
* **キーヒント:** 押すべきキーをキーキャップ風のバッジで表示（例: `j` / `Enter`）。

### 4.2 フォーカスモードとの関係

チュートリアル表示中は新たなフォーカスモード **`tutorial`** を導入する（既存の Column / Card / Edit / Command と並列）。チュートリアルは「下層フォーカスに被さる一時レイヤー」であり、終了時には元のフォーカス状態へ復帰する。

`tutorial` モードは、ステップの種類に応じて **2 つの相互作用状態**を持つ。

| 状態 | 対象ステップ | フォーカスの所在 | キーの扱い |
|:---|:---|:---|:---|
| **Observe（観測）** | ハンズオンステップ（コアトラックの 2〜9 など） | 下層アプリ（Column / Card / Edit） | **`Escape` を含む全キーを下層へ透過。** オーバーレイは操作をブロックせず、アクション／フォーカス遷移を監視して完了条件を判定する。 |
| **Control（UI 操作）** | 読み物 / Next ステップ（Welcome・各紹介・完了） | コーチマーク自身 | `Enter`=Next、`Backspace` / `←`=Back、`Escape`=中断確認。下層アプリには伝播しない。 |

* ハンズオン中（Observe）に**チュートリアルを中断**したい場合は、`Tab` でコーチマークの操作部（Back / Next / Skip step / **Exit tutorial**）へフォーカスを移し、`Exit tutorial` を実行するか `Escape` を押す。クリックでも可。
* これにより、コアトラックのステップ 7「Escape で戻る」では `Escape` が下層アプリへ確実に届き、Card → Column などの上位フォーカス遷移が発生・検知される。**`Escape` がチュートリアル中断に奪われない**。
* 同様に、Edit フォーカス中の `Backspace`（文字削除）や Column フォーカス中の `Enter`（カードへ入る）も Observe 状態では下層へ透過する。Back / Next 等のチュートリアル操作は Control 状態（コーチマークにフォーカス）でのみ作用する。

> **実装メモ:** `docs/001-keybindings.md` 1.2 のフォーカスモデルに `tutorial` を追加し、`stateDiagram` にも反映する。`tutorial` からの離脱は、ハンズオンの完了検知（自動前進）と、明示的な Exit 操作の 2 経路。Observe 状態では `Escape` をキャプチャ／consume しないことを実装上の必須要件とする。

### 4.3 テーマ・アクセシビリティ

* ダーク / ライト両テーマに追従（`data-theme` 属性、`docs/003-roadmap.md` 3.9）。
* スポットライト・コーチマークはキーボードのみで完結（Tab / Enter / Escape）。
* `prefers-reduced-motion` を尊重し、ハイライトのアニメーションを抑制する。

## 5. 状態の永続化

### 5.1 保存項目

チュートリアルの状態は設定ストア（`SettingsStore`、SQLite の `app` 設定 JSON に相乗り。`docs/003-roadmap.md` 3.9 と同方式）に保存する。**DB スキーマ変更は行わない。**

| キー | 型 | 説明 |
|:---|:---|:---|
| `tutorial.prompted` | boolean | 初回起動ダイアログを表示済みか |
| `tutorial.completed` | boolean | チュートリアルを最後まで完了したか |
| `tutorial.lastStep` | number | 最後に到達したステップ番号（途中再開用） |
| `tutorial.version` | number | チュートリアル内容のバージョン（後述） |

### 5.2 再開と再実行

* チュートリアルを中断した場合は `tutorial.lastStep` を保存し、次回手動起動時に「最初から / 続きから」を選べるようにする。
* 完了済みでも手動起動した場合は常に最初から開始する（再学習のため）。

### 5.3 バージョニング

* チュートリアル内容を将来更新した場合、`tutorial.version` を上げる。
* `tutorial.completed = true` かつ保存済み `tutorial.version` が現行より古い場合、初回起動時のダイアログを「What's new」案内として再表示するか検討する（MVP では再表示しない。フラグだけ保持しておく）。

## 6. 練習環境の扱い

### 6.1 練習対象 Deck

* ハンズオンはユーザーの実データを汚さないよう、**専用のチュートリアル用 Deck**（または既存のオンボーディング「Getting Started」Deck）内で行わせる。
* 初回起動直後はオンボーディング Deck しか存在しないため、そのまま練習場所として利用できる。
* 既にユーザーが自分の Deck を作成済みの状態で手動起動した場合は、チュートリアル開始時に**一時的なサンドボックス Deck を生成**するか、現在の Deck をそのまま使うかを選ばせる。
  * MVP では「現在の Deck で実施（非破壊操作のステップのみハンズオン化し、作成系ステップは現在の Deck に練習カードを追加）」を基本とし、サンドボックス生成は将来拡張とする。

### 6.2 後始末

* チュートリアル中に作成した練習カードは、`deleted_with_column` ではなく通常の論理削除対象としてユーザーが任意に削除できる（`u` / `g t` で復元可能。`docs/002-data-structure.md`）。
* チュートリアル側からの自動削除は行わない（ユーザーの操作結果を勝手に消さない方針）。

## 7. MVP スコープ

### 7.1 MVP に含める

* 初回起動時の起動促しダイアログ（Start / Skip）
* コマンドパレット「Tutorial」コマンドからの手動起動
* §3.2 のコアトラック 11 ステップ（フォーカスモデル＋カラム管理＋削除・復元＋ゴミ箱 UI のハンズオン）
* §3.2.1 拡張トラック（任意・各ステップ単位でスキップ可能）
* スポットライト + コーチマーク + キーヒントの UI
* 完了 / 中断 / 途中再開フラグの永続化（`SettingsStore` 相乗り）
* ダーク / ライトテーマ追従
* アクティブキーバインドからのキー表記の動的解決

> 拡張トラックを MVP に含めるか、コアトラックのみを MVP とし拡張は後続にするかは、実装コストを見て調整可能。最低ラインはコアトラック。

### 7.2 MVP に含めない（将来拡張）

* サンドボックス専用 Deck の自動生成・自動破棄
* チュートリアルバージョン更新時の「What's new」再表示
* 機能別の独立ミニチュートリアル（拡張トラックの各項目を、その機能を初めて使う文脈でコンテキスト起動するガイド）
* 進捗のクラウド同期
* 多言語対応（現状は英語のみ。`docs/000-spec.md` 8.2）

## 8. 受け入れ基準

* 初回起動時に起動促しダイアログが 1 回だけ表示される。「Skip for now」を選ぶと次回以降は自動表示されない。
* コマンドパレット「Tutorial」からいつでも起動でき、完了済みでも最初から再実行できる。
* 各ハンズオンステップは、対応するアクション／フォーカス遷移の発生を正しく検知して次へ進む（キーバインドをカスタマイズしていても動作する）。
* コアトラックのステップ 7「Escape で戻る」で `Escape` を押すと、下層アプリのフォーカスが上位へ遷移し、その遷移が検知されて次へ進む（`Escape` がチュートリアル中断に奪われない）。
* 「Exit tutorial」（または読み物ステップでの `Escape`）で中断確認が出て、中断すると元のフォーカス状態へ復帰する。
* チュートリアルがユーザーの既存データを破壊しない。
* 完了 / 中断状態がアプリ再起動後も保持される。
