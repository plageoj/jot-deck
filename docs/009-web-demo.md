# Jot Deck Web デモ 設計書

## 1. 概要

### 1.1 目的

Jot Deck の価値はキーボード中心の操作感（フォーカスモデル、`h/j/k/l`、`g` プレフィックス）にあり、スクリーンショットや動画では伝わりにくい。Web デモは、**インストール前にブラウザでその操作感を試せる入口**を提供し、ランディングページからデスクトップ版のダウンロードへつなぐ。

### 1.2 位置づけ

Web デモは **Web 版（データを永続化してブラウザで常用できる版）の第一段階**であり、同じ URL（`app.jot-deck.com`）で最終的に Web 版に置き換わる（§8）。デモ段階ではデータを保存しない。

| | Web デモ（本書） | Web 版（最終形） | デスクトップ版 |
|:---|:---|:---|:---|
| 配信先 | `app.jot-deck.com` | `app.jot-deck.com` | インストーラ |
| データ永続化 | なし（メモリ上のみ。リロードで初期状態に戻る） | ブラウザ内ストレージ | SQLite ファイル |
| Reporter / MCP | 不可（存在のみ案内） | 不可（存在のみ案内） | 可 |
| 用途 | 操作感の試用 | 常用 | 常用 |

永続化を持たないことで、複数タブの書き込み競合（各タブが独立したメモリ DB を持つため発生しない）を Web 版の段階まで先送りでき、既存フロントエンドのまま早く公開できる。

### 1.3 設計方針

* **既存フロントエンドをそのまま使う:** `packages/app` の SvelteKit ビルドを、WASM SQLite バックエンド（`004-e2e-testing.md`）で静的配信する。デモ専用の画面やデータ層は作らない。
* **差分はビルドフラグで閉じる:** デモ固有の UI（バナー）はデモビルドでのみ有効にする。Web 版への移行時はこのフラグを外すだけで済むようにする。ブラウザ開発サーバ（`pnpm dev`）と E2E の挙動は変えない。
* **Tauri 専用機能は隠すか案内に置き換える:** 押しても何も起きない UI を残さない。この扱いはデモ固有ではなくブラウザ実行全般のもの（`isTauri()` で判定）とし、Web 版でもそのまま使う。
* **トラッキングしない:** Cookie や独自の解析スクリプトは入れない。

## 2. 配信

* 配信先: `app.jot-deck.com`（Cloudflare Pages の独立プロジェクト）。Web 版も同じ URL で配信するため、デモ段階から「アプリ本体の URL」として案内してよい。ランディングページ（`jot-deck.com`、`packages/web`）とは別プロジェクトにし、SvelteKit の `paths.base` を変えずにルート配信する。
* ビルド: `packages/app` を `VITE_JOT_DECK_DEMO=1` 付きで `vite build` し、`adapter-static` の出力（SPA fallback `index.html`）を配信する。Tauri や Rust のビルドは不要。
* 公開タイミング: `main` へのマージごとに自動デプロイする。デスクトップ版の Production / Preview チャンネル（`005-release.md`）とは連動させない。
* ランディングページのヒーローと CTA 付近に「Try in browser」リンクを置く。

---

## 3. 初期状態

* 起動時は空のメモリ DB から始まり、既存の初回起動処理によって「Getting Started」オンボーディング Deck（`Welcome` / `Navigation` / `Tips`）が作られて開く。デモ用に別のシードは持たない。
* オンボーディング Deck の内容はデモでもデスクトップ版でも同じとし、操作の読み物と練習場所を兼ねる。
* 設定（テーマ、フォント、Vim モード、キーバインド上書き）は DB に保存されるため、リロードで既定値に戻る。フォーカス位置は `localStorage` に残るが、既存のクランプ処理で整合する。

---

## 4. デモ固有の UI

デモビルドでのみ表示する。

### 4.1 デモバナー

* 画面上部に常時 1 行のバナーを出す: 「Web demo — nothing is saved. Download the desktop app」。ダウンロード先は `jot-deck.com` のダウンロード節。
* 閉じるボタンは置かない。フォーカスを奪わず、キーボード操作の対象にもしない（Tab 移動でも到達するリンクのみ）。
* カラム領域の高さはバナーの分だけ縮める。
* 保存されないことはバナーで常に示すため、タブを閉じるときの離脱確認（`beforeunload`）は出さない。

### 4.2 小さい画面・タッチ端末

* `pointer: coarse` かつ幅が狭い環境では、最初に「Jot Deck is keyboard-driven. Try it on a desktop browser.」の案内を出す。閉じれば、そのまま操作できる。
* モバイル向けのレイアウト調整はしない。

### 4.3 アプリ情報

* About ダイアログのバージョン表記は「Web demo」とし、アップデート確認ボタンは出さない。
* ウィンドウタイトルは「Jot Deck — Web demo」とする。

## 5. Tauri 専用機能の扱い

| 機能 | デモでの扱い |
|:---|:---|
| Reporters（`g r`、`ReportersDialog`） | ダイアログを開くと登録 UI の代わりに「Reporters stream speech and other inputs into cards. Available in the desktop app.」とダウンロードリンクを表示する |
| Deck スイッチャーの「Copy MCP server config」 | 表示しない |
| Deck スイッチャーの「Deck id」コピー | 表示しない（ブラウザ内の Deck には外部の MCP ブリッジから届かないため） |
| アップデータ | 動作させない（§4.3） |
| 外部変更の観測（`external-db-change` / `reporter-change`） | 動作させない（既存の `isTauri()` ガードのまま） |
| 外部リンクを開く | ブラウザの新しいタブで開く（既存の fallback） |

コマンドパレットのコマンドは削らない。上の機能を呼ぶコマンドも、実行時の表示で案内する。

## 6. ブラウザのショートカットとの衝突

ブラウザが予約していて `preventDefault` できないキーは、デモでは効かない。いずれも代替キーがあるため、キーバインド自体は変えない。

| キー | 衝突 | 代替 |
|:---|:---|:---|
| `Ctrl+t`（カラム切り替え） | Chrome / Edge / Firefox で新しいタブ | `g n` / `g c` |
| `Ctrl+Shift+P`（コマンドパレット） | Firefox でプライベートウィンドウ | `F1` |

* デモビルドでは、キーバインドチートシート（`?`）でこれらのキーに「Desktop only」の注記を付け、代替キーを先に表示する。
* `Ctrl+p` / `Ctrl+r` / `Ctrl+d` / `Ctrl+z` / `Ctrl+,` / `F1` は `preventDefault` で取れるため、デスクトップ版と同じに動く。

## 8. Web 版への移行

デモの次の段階として、`app.jot-deck.com` の配信物をデータを永続化する Web 版に差し替える。URL は変えない。

### 8.1 前提となる実装

* **永続化:** ブラウザ内ストレージ（IndexedDB または OPFS）に DB を保存し、リロード後も残す。
* **複数タブの書き込み安全:** sql.js は DB 全体を書き出すため、複数タブが同時に書くと最後に書いたタブの内容で上書きされる。Web Locks で書き込みタブを 1 つに限り、他のタブは読み取り専用（または操作不可の案内）から始める。

### 8.2 差し替え時の変更

* デモビルドフラグを外したビルドを配信する。デモバナー（§4.1）はなくなる。
* デスクトップ版へのダウンロード導線は、Reporter / MCP の案内（§5）と About ダイアログに残す。
* About のバージョン表記とウィンドウタイトルは「Web」とする。
* Tauri 専用機能の扱い（§5）、ブラウザのショートカットとの衝突（§6）、小画面向けの案内（§4.2）は変えない。
* デモのデータは保存されていないため、データ移行は不要。
* 差し替えと同時に、本書を Web 版の設計書として書き改める。

## 9. 受け入れ基準

* `app.jot-deck.com` を開くと、インストールなしで「Getting Started」Deck が表示され、キーボードだけでカードの作成・編集・移動・削除・復元ができる。
* デモバナーが常に表示され、ダウンロード先へ遷移できる。
* Reporters / MCP 設定コピー / Deck id コピー / アップデート確認が、押しても何も起きない状態で残っていない。
* `pnpm dev` と E2E（`pnpm --filter app test:e2e`）の挙動はデモビルド導入前と変わらない。
